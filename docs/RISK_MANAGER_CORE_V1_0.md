# TradeMind Risk Manager Core 1.0

## Назначение

Risk Manager является обязательной прослойкой между подтверждённым торговым
сценарием и будущим модулем исполнения.

Аналитический движок отвечает на вопрос:

> Есть ли качественный и статистически подтверждённый сетап?

Risk Manager отвечает на другой вопрос:

> Можно ли безопасно исполнить этот сетап на конкретном счёте и каким объёмом?

Один и тот же сигнал получает разный размер позиции на счетах с разным
балансом, эквити, доступной маржой, уже открытым риском и пользовательскими
лимитами.

Версия 1.0 не подключается к брокеру и не отправляет ордера. Она принимает
готовые снимки данных и возвращает только `ALLOW` или `BLOCK`.

## Входные данные

### 1. Signal passport

Risk Manager принимает неизменяемый кандидат v1.16 и состояние публикационного
фильтра.

По умолчанию разрешён только статус:

```text
PUBLISHABLE
```

`SHADOW_ONLY` и `REJECTED` нельзя превратить в реальную сделку простым расчётом
лота.

### 2. Account snapshot

Снимок счёта содержит:

- идентификатор и площадку: MT5, Bybit или generic adapter;
- валюту счёта;
- время снимка;
- balance и equity;
- free margin и used margin;
- максимум equity для расчёта текущей просадки;
- equity на начало торгового дня;
- разрешение торговли со стороны брокерского адаптера.

Устаревший или пришедший из будущего снимок блокирует сделку.

### 3. Instrument specification

Спецификация инструмента передаёт значения в валюте счёта:

- tick size;
- tick value на одну единицу объёма;
- минимальный, максимальный и шаг объёма;
- корреляционную группу;
- модель маржи.

Для MT5 адаптер в будущем должен получать эти значения из символа и
`OrderCalcMargin`. Для линейных контрактов Bybit допустима модель:

```text
margin = entry × contract_size × volume × conversion_rate / leverage
```

### 4. Portfolio snapshot

Для каждой уже открытой позиции передаётся риск до защитного стопа в валюте
счёта. Если хотя бы у одной позиции риск неизвестен, строгий профиль блокирует
новую сделку. Открытая позиция без определённого риска не должна маскироваться
нулём.

### 5. Risk profile

Профиль пользователя задаёт:

- риск на одну сделку;
- максимальный риск одной сделки;
- лимит суммарного портфельного риска;
- лимит риска по одному символу;
- лимит риска по корреляционной группе;
- дневной стоп;
- максимальную просадку счёта;
- лимиты маржи;
- максимальное число одновременно открытых сделок;
- допустимую свежесть сигнала и брокерских данных;
- консервативный запас на проскальзывание.

## Формула размера позиции

По умолчанию денежная база риска равна меньшему из balance и equity:

```text
risk_basis = min(balance, equity)
```

Денежный бюджет сделки:

```text
risk_budget = risk_basis × risk_percent / 100
```

Для каждого входа лесенки:

```text
entry_risk_budget = risk_budget × allocation
price_risk = abs(adverse_entry - stop)
risk_per_volume = price_risk / tick_size × tick_value_per_volume
raw_volume = entry_risk_budget / risk_per_volume
```

Объём всегда округляется вниз по шагу брокера. Округление вверх запрещено,
потому что оно может превысить заданный риск.

`adverse_entry` включает пользовательский запас на проскальзывание в худшую
сторону:

- для BUY цена входа увеличивается;
- для SELL цена входа уменьшается.

## Лесенка входов

Риск задаётся на весь сценарий, а не отдельно на каждую заявку.

Пример:

```text
Общий риск: 0.50% счёта
Entry 1: 50% риска
Entry 2: 30% риска
Entry 3: 20% риска
```

Если все заявки исполнятся и сработает общий стоп, суммарный убыток не должен
превысить общий бюджет риска с учётом заданного проскальзывания.

Если минимальный лот брокера на одной из обязательных ступеней уже превышает её
риск-бюджет, версия 1.0 блокирует весь план. Она не удаляет ступень молча и не
подгоняет стоп под лот.

## Жёсткие блокировки

Состояние `BLOCK` возвращается, когда выполняется хотя бы одно условие:

- сигнал не прошёл publication gate;
- сигнал создан не из рыночных данных;
- символ, площадка или валюта модели не совпадают;
- данные счёта или сигнал устарели;
- торговля на счёте отключена;
- запрошенный риск выше пользовательского лимита;
- достигнут дневной стоп;
- достигнут лимит общей просадки;
- риск существующей позиции неизвестен;
- превышено число открытых сделок;
- минимальный лот превышает допустимый риск;
- требуемый объём превышает максимум брокера;
- превышен портфельный, символный или корреляционный риск;
- отсутствует обязательная модель маржи;
- не хватает свободной маржи;
- нарушен минимальный резерв free margin;
- превышен лимит использования маржи.

## Результат

Risk Manager возвращает JSON с:

- `ALLOW` или `BLOCK`;
- точным денежным бюджетом;
- фактическим риском после округления;
- объёмом каждой ступени;
- маржой каждой ступени;
- риском портфеля после сделки;
- риском символа и корреляционной группы;
- дневной потерей и текущей просадкой;
- машинными кодами всех причин блокировки;
- предупреждениями;
- неизменяемым `decision_id`.

`ALLOW` означает только прохождение риск-проверки. Версия 1.0 всё равно имеет:

```text
orders_enabled = false
broker_api_called = false
```

## CLI

```powershell
.\.venv\Scripts\python.exe -m trademind.risk_manager `
  --passport .\data\signals\passport.json `
  --account .\data\risk\account.json `
  --instrument .\data\risk\EURUSD.json `
  --profile .\config\risk_profiles\standard_v1.json `
  --portfolio .\data\risk\portfolio.json `
  --output .\data\risk\decision.json `
  --journal .\data\signal_intelligence\events.jsonl
```

При работе напрямую с кандидатом требуется явно передать состояние gate:

```powershell
--candidate candidate.json --gate-state PUBLISHABLE
```

## Следующие адаптеры

Risk Manager Core не должен знать детали API площадок. Отдельные адаптеры будут:

1. читать balance, equity, margin и позиции MT5;
2. получать tick value и расчёт маржи через MetaTrader;
3. читать кошелёк, позиции и спецификации Bybit;
4. переводить открытые позиции в stop-defined risk;
5. передавать свежий нормализованный snapshot в Core;
6. принимать решение Core, но не иметь права обходить `BLOCK`.

После проверки на реальных снимках появится полуавтоматический слой с кнопкой
подтверждения. Полный автомат не входит в Risk Manager Core 1.0.
